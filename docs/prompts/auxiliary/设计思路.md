为了方便在 **VitePress** 中维护、生成侧边栏以及后续持续扩充，建议按“主题域（一级目录） → 能力模块（二级目录） → 最小必要原子知识点（单篇 `.md`）”的三层嵌套结构来组织。

### 设计原则

1. **单篇原子化（最小必要知识点）**：每个 `.md` 只讲透一个核心概念或强关联的小组（比如把 `const` 修饰符和 `const_cast` 拆开，把“值类别”和“移动语义/完美转发”拆开），篇幅控制在 800–1500 字左右，既方便费曼输出，也方便 VitePress 侧边栏精准定位。
2. **语义化扁平文件名**：目录做适度分层（不超过 3 层，避免侧边栏过深），文件名用 `kebab-case`（如 `01-const-and-mutable.md`），不带冗余后缀，便于脚本自动生成侧边栏和跨篇链接。
3. **与大纲一一映射**：附件大纲共 82 个知识点（6 大模块），以下结构完整覆盖全部 82 项，并将高密度复合点（如“指针/引用/值类别”、“移动语义/转发”、“虚函数/继承/布局”）拆解为更清晰的独立页面。

### 单篇 `.md` 内部层次模板建议

为了保证每篇文章都层次分明、便于复习和面试检索，建议统一采用以下 5 段式骨架：

```markdown
# 标题：核心概念名称

> **一句话定位**：用 1–2 句话说明它解决什么问题、属于哪一层抽象。

## 1. 核心机制与语法要点
- 拆解关键规则、语法形式与边界条件

## 2. 底层原理与内存/执行视角
- 说明编译器如何处理、内存布局或运行时行为变化（必要时附简图或最小代码）

## 3. 常见陷阱与 UB 雷区
- 列出高频踩坑点、未定义行为（UB）与错误直觉纠偏

## 4. 工程选型与实践建议
- 结合后端/游戏服务端场景给出取舍标准

## 5. 面试高频追问自检
- 列出 2–3 个典型追问要点，方便自测

```

### VitePress 落地小贴士

* **每个子目录放 `index.md**`：点击侧边栏模块分组标题时能直接进入该模块导读页，避免空链接或路由跳转空白。
* **数字前缀控制排序**：文件名统一加 `01-`、`02-` 前缀，自动生成侧边栏时无需手写大量排序配置，新增知识点也只需在对应模块末尾追加编号。
* **章节级大纲页作为索引**：`06-evolution-and-engineering/standards-evolution/` 下的版本演进篇非常适合做成“索引/串联页”，把前面分散在各模块里的 C++11~C++23 特性串起来并交叉链接。
